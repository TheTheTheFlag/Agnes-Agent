## 三、核心概念

### 3.1 什么是 Agent（智能体）

- 广义：能够**感知环境 → 做出决策 → 执行行动**以实现特定目标的自主系统（李飞飞团队《Agent AI》定义）。
- LLM 语境：以**大语言模型（LLM）为大脑**，通过**工具调用**与外部世界交互、自主完成复杂任务的系统，又称 LLM Agent / AI Agent。
- 微软、谷歌、IBM、Salesforce 等厂商定义细节略有差异，但共识点是：**Agent = LLM + 记忆 + 规划 + 工具 + 行动**。

### 3.2 关键区别

| 对比维度 | 传统 AI（工具型 AI / Chatbot） | AI Agent |
|---|---|---|
| 交互方式 | 单轮、响应式 | 多轮、任务导向、持续运行 |
| 行动能力 | 只回答问题 | 主动调用工具、执行多步任务 |
| 记忆 | 无或弱 | 短/长期记忆、状态保持 |
| 规划 | 无 | 自主分解任务、动态调整 |
| 典型形态 | 客服机器人、识别系统 | 数字员工、自主执行体 |

### 3.3 演进阶梯

- **Chatbot**：人类完成绝大部分工作，AI 提供信息与建议。
- **Copilot**：人机协作、工作量相当，AI 出初稿、人做确认。
- **Agent**：AI 完成绝大部分工作，人类设定目标、提供资源、监督结果。

### 3.4 核心组件（学术界视角）

- 复旦 NLP：**Brain（大脑）/ Perception（感知）/ Action（行动）** 三大模块。
- 人大高瓴：**Profile / Memory / Planning / Action** 四大模块。
- 产业界归纳：**感知 → 决策 → 规划 → 行动 → 记忆 → 反思** 的能力闭环。

## 四、关键特性

1. **自主性（Autonomy）**：接收目标后自主拆解任务、选择路径并执行，低监管依赖。
2. **工具调用（Tool Use）**：调用 API、数据库、搜索引擎、代码执行器、甚至其他 Agent，突破模型能力边界。
3. **记忆系统（Memory）**：工作记忆（对话上下文）、长期记忆（历史、偏好、画像），支撑连续性与个性化。
4. **规划能力（Planning）**：将复杂目标分解为子任务/子步骤，支持动态调整与自我修正（ReAct、反思机制）。
5. **感知与行动闭环**：持续监测环境反馈，判断是否达成预期，形成"感知-决策-执行"循环。
6. **协作能力（Collaboration）**：多智能体协作、人机协作（Human-in-the-Loop）、工具间协同。
7. **适应与学习**：随交互积累优化策略，越用越好用（企业级报告结论）。

## 五、应用场景

| 场景 | 说明 | 典型示例 |
|---|---|---|
| 智能客服 | 多轮对话、自动查询、工单处理 | 客服自动响应、售前咨询 |

| IT 运维自动化 | 故障排查、自动化运维 | IT 自动化、告警处理 |
| 多智能体协作 | 多角色分工协同完成复杂任务 | 多智能体客服系统、Agent 团队 |

## 六、分类与主流框架

### 6.1 按产品形态分类
- **通用智能体应用**：面向终端用户的开箱即用助手（搜索、写作、代码、邮件等多步任务）。
- **智能体搭建平台 / 开发框架**：面向开发者/企业的低代码、模块化构建平台（LLM 接入、工具集成、记忆模块、流程编排、插件市场）。

### 6.2 按架构分类
- **单智能体**：一个 Agent 独立完成目标。
- **多智能体**：多个专业 Agent 协作，通过路由/消息机制分工。

### 6.3 主流框架速览
| 框架 | 特点 |
|---|---|
| **LangGraph** | 图结构编排（节点/边/状态/条件边），支持状态管理、checkpoint 时间旅行、人机协作，适合复杂工作流与多智能体 |
| **LangChain / LangSmith** | Agent 组件与可观测性生态 |
| **AutoGPT / BabyAGI** | 自主规划任务链的早期代表 |
| **Coze / Dify / 百炼等平台** | 低代码智能体搭建平台，内置模板与插件市场 |

> 本项目（Agnes-Agent）即基于 LangGraph 构建：模型自决路由、5 层记忆、工具调用、规划-执行-验证循环、Web 调试面板——是本文档的最佳实践参照。
