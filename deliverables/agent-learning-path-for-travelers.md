## 一、课程设计原则与总览

### 1.1 五个设计原则

| # | 原则 | 含义 | 落实方式 |
|---|------|------|----------|
| 1 | **从零可入** | 不设编程前置，第一周就出成果 | 阶段一先学"用 AI"再学"写代码"；命令行、Python 从零教 |
| 2 | **先甜后苦** | 先用提示词做出"能用"的东西，再逐步深入原理 | 第 1~2 周产出对话版旅行助手；第 9 周起升级为真 Agent |
| 3 | **旅行场景贯穿** | 每阶段项目都围绕旅行，学完立刻用在下一次旅行 | 统一主线：**智能旅行行程规划 Agent**（见第九章） |
| 4 | **可衡量验收** | 每阶段有"能演示、能量化、能放进作品集"的产出 | 每章末尾附《本阶段验收标准》，全部打勾才进入下一阶段 |
| 5 | **碎片化可续跑** | 适配上班族/家长被旅行、带娃打断的现实 | 每阶段拆成最小完成单元；断点恢复策略见第十二章 |

### 1.2 一句话学习主线

> **输入"目的地 + 人数 + 天数 + 偏好 + 预算" → 检索攻略知识库（RAG） → 调用实时工具（天气/地图/票价） → 生成带引用的行程 → 关键操作人工审批 → 可部署上线分享给家人/客户。**

所有阶段都朝这条主线收敛：阶段一实现"对话版"，阶段二实现"脚本版"，阶段三加入"知识库"，阶段四加入"工具调用"，阶段五加入"记忆与多智能体"，阶段六实现"上线"。

### 1.3 学习节奏总建议

- **每天**：碎片时间 20~40 分钟（通勤、候机、排队时用手机看概念、刷提示词练习）；
- **每周**：1 次 2~3 小时完整动手时段（周末集中敲代码、跑通脚本）；
- **总周期**：约 16~18 周（4~5 个月），每周一个最小完成单元；
- **降级路径**：时间紧张的旅行者可砍掉阶段五多智能体（不影响毕业项目主体），或把阶段六部署简化为本地运行 + 录屏演示。

## 二、六阶段递进模型（总览表）

| 阶段 | 主题 | 周期 | 核心知识点 | 工具链（本阶段新增） | 项目实战产出（里程碑） | 对应 AI Agent 关键技能 |
|------|------|------|-----------|----------------------|------------------------|------------------------|
| **一** | AI 认知与提示工程 | 第 1~2 周 | 大模型基本概念（Token/上下文/温度）、提示词结构、Few-shot、CoT、结构化输出 | ChatGPT / DeepSeek / Kimi / 通义 | 对话版"旅行规划问答助手"（纯提示词） | 提示工程（Prompt） |
| **二** | Python 基础 + LLM API 编程 | 第 3~5 周 | Python 语法、终端、pip/venv、HTTP 请求、OpenAI 兼容 API、流式输出、Key 安全 | Python 3.11+、VS Code、终端、DeepSeek/通义 API | 命令行脚本 `travel_cli.py`：一句话生成 JSON 行程 | LLM API 集成、代码能力 |
| **三** | RAG 与知识库 | 第 6~8 周 | Embedding、向量数据库、文档切分、相似度检索、RAG 原理、引用溯源 | Chroma/FAISS、sentence-transformers、LangChain（可选） | "舟山亲子游攻略知识库"：带引用的问答 Agent | RAG 检索增强 |
| **四** | Agent 框架与工具调用 | 第 9~11 周 | ReAct、Function Calling、Agent 循环、LangGraph 图结构、状态、条件路由、人工审批节点 | LangGraph、LangChain、天气/地图/票价 API | Agent 自动查天气/票价并编排行程生成流程 | 工具调用、Agent 编排 |
| **五** | 记忆、规划与多智能体 | 第 12~14 周 | 短期/长期记忆、任务规划与分解、Supervisor/Worker 多智能体、反思修正 | LangGraph 记忆节点、Redis/SQLite、Supervisor 模式 | 四角色多智能体：规划+检索+天气+预算，主管协调 | 记忆、规划、多智能体 |
| **六** | 评测、安全与部署 | 第 15~18 周 | 评测体系、幻觉控制、Prompt 注入防护、成本控制、日志观测、FastAPI/Gradio 部署 | FastAPI、Gradio/Streamlit、Docker（可选）、Langfuse（可选）、Railway/云服务器、GitHub | 部署上线"行程咨询助手"网页，附 README 与评测报告 | 评测、安全、部署运维 |

> **逻辑递进关系**：一（会提问）→ 二（会编程调模型）→ 三（会喂知识）→ 四（会调用外部工具）→ 五（会记忆与协作）→ 六（会交付上线）。
> 每阶段技能是下一阶段的**前置依赖**：不会提示词就无法设计 Agent 的系统提示词；不会 API 就无法做 RAG；不会 RAG 与工具调用就无从谈 Agent 编排。

## 三、阶段一：AI 认知与提示工程（第 1~2 周）

### 3.1 学习目标

- 会用至少 2 个主流 AI 对话工具，理解"向 AI 提问"的本质是**写提示词**；
- 能写出结构化的提示词（角色 + 任务 + 约束 + 示例 + 输出格式），稳定得到想要的结果；
- 能理解 Token、上下文窗口、温度等基本概念，知道它们如何影响输出。

### 3.2 核心知识点

| 知识点 | 说明 | 旅行者版例子 |
|--------|------|--------------|
| 大模型基本原理 | Token 计费、上下文窗口、概率生成 | "为什么回答长度和价格有关？" |
| 提示词四要素 | 角色、指令、约束、示例（Few-shot） | "你是资深亲子游规划师，帮我规划舟山 3 日行程，不爬山、中午要有午休" |
| 思维链 CoT | 让模型分步推理，提升复杂任务准确率 | "先列出要考虑的因素（孩子年龄/交通/天气），再给出建议" |
| 结构化输出 | 用格式约束得到 JSON / 表格 | "以 JSON 输出：{destination, days, schedule:[]}" |
| 温度与采样 | 温度高=创意多、低=稳定 | 生成"备选路线"用 0.7，生成"行程表"用 0.2 |
| 常见坑 | 幻觉、过时信息、指令被忽略 | "不要编造门票价格，不确定就说不知道" |

### 3.3 工具链

- **对话工具**：DeepSeek / ChatGPT / Kimi / 通义千问（任选 2 个，优先国产免费额度高的）；
- **提示词调试法**：迭代对比法（同一问题改一个变量，对比输出差异）；
- 无需安装任何软件，手机即可完成本阶段。

### 3.4 项目实战（里程碑 1：对话版旅行助手）

- **任务**：用纯提示词（不写代码）做一个"旅行规划问答助手"，覆盖 3 个场景：行程生成、亲子适配建议、避坑提示；
- **要求**：所有输出统一为 JSON 结构，便于后续阶段直接复用；
- **产出**：一份《提示词手册.md》，收录 10 条已调通的提示词 + 效果对比截图。

### 3.5 本阶段验收标准

- [ ] 能用提示词稳定输出 JSON 格式行程（连续 5 次不跑偏）；
- [ ] 能解释 Token、上下文、温度三个概念；
- [ ] 能指出模型输出中的 1 处幻觉并修正提示词规避。

## 四、阶段二：Python 基础与 LLM API 编程（第 3~5 周）

### 4.1 学习目标

- 掌握 Python 最小可用子集，能读写脚本、处理数据、捕获异常；
- 能调用 OpenAI 兼容的 LLM API，把阶段一的提示词"代码化"；
- 能安全管理 API Key（不写进代码、不提交到 GitHub）。

### 4.2 核心知识点

| 知识点 | 说明 | 旅行者版例子 |
|--------|------|--------------|
| Python 基础 | 变量、类型、列表/字典、函数、循环、条件 | 用字典存"目的地-偏好-预算" |
| 文件与 JSON | 读写文件、json 序列化 | 把生成的行程保存为 .json/.md |
| 异常处理 | try/except、超时处理 | API 报错时给出友好提示而非崩溃 |
| 命令行与包管理 | 终端、`pip install`、venv 虚拟环境 | 装 `openai`、`python-dotenv` |
| HTTP 与 API | 请求、鉴权、`/v1/chat/completions` | 调 DeepSeek/通义（OpenAI 兼容协议） |
| 流式输出 | stream=True 逐字显示 | 终端里像聊天一样滚动输出 |
| 安全实践 | .env 存 Key、gitignore | Key 泄露后如何吊销重置 |

### 4.3 工具链

- **Python 3.11+**（官网安装，勾选 Add to PATH）；
- **VS Code** + Python 插件（或 PyCharm Community）；
- **终端**（Windows 用 PowerShell / 终端；macOS 用 Terminal）；
- **LLM API**：DeepSeek（OpenAI 兼容，成本极低）或通义百炼，注册后获取 API Key；
- **库**：`openai`、`python-dotenv`、`requests`。

### 4.4 项目实战（里程碑 2：命令行脚本 travel_cli.py）

- **功能**：`python travel_cli.py --city 舟山 --days 3 --people 2 --kids 1` → 调用 LLM API → 输出 JSON 行程 + 保存为 markdown；
- **进阶**：加入"多轮追问"（先问偏好再生成）、错误重试、把历史行程存档；
- **产出**：可运行的脚本 + 3 份真实行程输出（用你自己的旅行计划测试）。

### 4.5 本阶段验收标准

- [ ] 脚本能在新电脑上 10 分钟内从零跑通（文档化安装步骤）；
- [ ] 能读懂并修改别人写的基础 Python 代码（如改行程天数）；
- [ ] 知道 API Key 的三种错误放法（硬编码/提交 GitHub/截图外发）并全部规避。

## 五、阶段三：RAG 检索增强与知识库（第 6~8 周）

### 5.1 学习目标

- 理解 RAG 原理：**检索 → 增强 → 生成**，明白"为什么 RAG 能减少幻觉"；
- 能构建一个小型攻略知识库（切分、向量化、存储、检索）；
- 让 Agent 的回答**带引用来源**，用户可溯源验证。

### 5.2 核心知识点

| 知识点 | 说明 | 旅行者版例子 |
|--------|------|--------------|
| Embedding 词嵌入 | 文本 → 向量，语义相似度 | "适合亲子"和"带娃友好"语义相近 |
| 文档切分 | chunk 大小/重叠、按语义切分 | 把攻略按"景点/美食/住宿"分段 |
| 向量数据库 | Chroma/FAISS 存储与检索、top-k | 从 100 篇攻略中召回最相关的 5 段 |
| RAG 全流程 | 索引 → 检索 → 拼接上下文 → 生成 | 回答"舟山哪适合 5 岁孩子"时先检索再回答 |
| 引用溯源 | 让模型输出来源片段 | 回答末尾附"来源：舟山亲子游攻略.md 第 3 段" |
| 知识库维护 | 更新、去重、版本管理 | 攻略更新后重新索引 |

### 5.3 工具链

- **向量库**：ChromaDB（本地零配置，首选）或 FAISS；
- **Embedding**：sentence-transformers（本地免费）或 API Embedding；
- **编排库**：LangChain（LCEL 链式调用，可选但推荐）；
- **素材**：复用本环境已有的《舟山亲子游攻略.md》《舟山亲子游行程规划.md》作为首个知识库，后续替换为自己的攻略。

### 5.4 项目实战（里程碑 3：带引用的攻略问答 Agent）

- **功能**：输入"舟山 3 天亲子游，不爬山、孩子 5 岁，有什么推荐？" → Agent 检索知识库 → 输出带引用的回答 + 可直接用的行程建议；
- **进阶**：支持多文档知识库、追问"上一条的依据是什么"；
- **产出**：`qa_agent.py` + 知识库目录 + 10 条测试问答与人工评分表。

### 5.5 本阶段验收标准

- [ ] 同一问题**有知识库**的回答明显比**纯 LLM** 更具体、更少幻觉（对比记录）；
- [ ] 回答能定位到原文片段（引用可点击/可回查）；
- [ ] 能对"知识库里没有的信息"诚实回答"暂无资料"，而不是编造。

## 六、阶段四：Agent 框架与工具调用（第 9~11 周）

### 6.1 学习目标

- 理解 Agent 核心循环：**LLM 决策 → 调用工具 → 观察结果 → 再决策**（ReAct 模式）；
- 能用 Function Calling / Tool Calling 让模型自主决定调用哪些外部 API；
- 会用 LangGraph 把流程画成"图"：节点（Node）、边（Edge）、状态（State）、条件路由、人工审批节点。

### 6.2 核心知识点

| 知识点 | 说明 | 旅行者版例子 |
|--------|------|--------------|
| 工具调用 Tool Calling | 给模型注册工具 schema，模型输出结构化调用请求 | 注册 `get_weather(city, date)` 工具 |
| ReAct 循环 | 推理（Reason）→ 行动（Act）→ 观察（Observe） | 先问"几号出发？"再查天气 |
| LangGraph 图结构 | 节点/边/状态机，可视化编排 | 意图识别 → 规划 → 检索 → 工具 → 生成 |
| 条件路由 | 根据状态决定走哪条边 | 有娃 → 走"亲子过滤"分支；无娃 → 跳过 |
| 状态管理 | State 共享、Reducer 合并 | 把用户偏好、检索结果、天气都放进状态 |
| 人工审批节点 | interrupt 暂停等待人确认 | 下单订酒店/购票前必须人工确认 |
| 工具 API 接入 | 天气（Open-Meteo 免费）、地图、票价 | 自动填充"未来 7 天天气 + 交通耗时" |

### 6.3 工具链

- **LangGraph**（核心框架，pip 安装）；
- **LangChain**（工具与检索封装）；
- **免费实时数据**：Open-Meteo（天气）、高德/百度地图开放平台（POI/路线）、12306/景区官网抓取或官方 API（票价，注意合规）；
- **可观测**：LangSmith 或 Langfuse（可选，观察每一步调用）。

### 6.4 项目实战（里程碑 4：会调用工具的行程 Agent）

- **功能**：用户输入目的地与日期 → Agent 自主查询未来天气 → 检索攻略知识库 → 过滤不适合的行程（如雨天改室内） → 生成行程 → 涉及"订票/订房"动作停在人工审批节点；
- **进阶**：支持"再帮我查一下备选方案"的多轮工具调用；
- **产出**：`travel_agent.py`（LangGraph 图）+ 流程图（mermaid）+ 3 个完整运行日志。

### 6.5 本阶段验收标准

- [ ] 能画出自己 Agent 的 LangGraph 结构图并解释每个节点职责；
- [ ] Agent 能**自主决定**何时调用工具（而不是每次都调）；
- [ ] 关键操作（花钱/下单）默认走到人工审批节点，不会自动执行。

## 七、阶段五：记忆、规划与多智能体（第 12~14 周）

### 7.1 学习目标

- 让 Agent 具备**短期记忆**（多轮对话上下文）与**长期记忆**（跨会话记住用户偏好）；
- 让 Agent 学会**任务规划**：把"规划一次旅行"拆成可执行的子任务；
- 理解**多智能体协作**模式（Supervisor/Worker），体验角色分工与协同。

### 7.2 核心知识点

| 知识点 | 说明 | 旅行者版例子 |
|--------|------|--------------|
| 短期记忆 | 对话历史注入、窗口裁剪 | 记住用户上一轮说"孩子怕走路" |
| 长期记忆 | 向量存储/摘要存储，跨会话持久化 | 记住"用户喜欢住民宿、预算 3000" |
| 任务规划 | 计划生成、任务分解、顺序/并行执行 | "先查目的地 → 再查天气 → 再排行程" |
| 反思与修正 | 自我检查、根据反馈重做 | 生成行程后自检"是否超预算"并修正 |
| 多智能体模式 | Supervisor（主管）分配任务给 Worker | 主管把任务分给：攻略 Agent/天气 Agent/预算 Agent |
| 多智能体通信 | 共享状态、消息传递、结果汇总 | 各 Worker 结果写回共享状态，主管汇总 |

### 7.3 工具链

- **LangGraph**：记忆节点（checkpointer + 向量存储）、`create_react_agent`、Supervisor 模式（`langgraph-supervisor`）；
- **存储**：SQLite（本地零配置）/ Redis（进阶）；
- **Embedding**：复用阶段三的向量库做长期记忆。

### 7.4 项目实战（里程碑 5：四角色多智能体系统）

- **角色**：`主管 Planner`（拆任务、汇总）、`攻略检索 Agent`（RAG）、`实时信息 Agent`（天气/地图）、`预算 Agent`（记账与超支提醒）；
- **流程**：主管接收需求 → 并行派活 → 汇总 → 自检（预算/可行性）→ 输出最终行程；
- **记忆**：第二次使用时自动记住用户偏好（"上次你说不住景区里"）；
- **产出**：`multi_agent.py` + 一次完整多智能体协作运行日志 + 记忆持久化演示（重启后还记得）。

### 7.5 本阶段验收标准

- [ ] 重启程序后，Agent 能回忆起上次会话的用户偏好；
- [ ] 能把一个复杂请求自动分解为 ≥3 个子任务并分派给对应 Worker；
- [ ] 能演示"自检发现问题 → 修正后重新输出"的过程。

### 8.2 核心知识点

### 8.3 工具链

- **FastAPI**（后端）、**Gradio / Streamlit**（前端界面，新手首选 Gradio）；

### 8.4 项目实战（里程碑 6：上线"行程咨询助手"）
