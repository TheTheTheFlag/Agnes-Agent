## 一、一页纸速览（适合开场白）

> 开场一句话：**"大模型有知识，但缺'你自己的知识'；知识增强的三种做法，分别解决'找得到、理得清、想得通'。"**

### 1. RAG —— 检索增强生成（Retrieval-Augmented Generation）

- **一句话定位**：把外部文档*检索出来拼进提示词*，让大模型"看着资料答题"，工程最成熟、上手最快。
- **核心流程**：文档切块 → 向量化入库 → 按问题做相似度检索 Top-K → 拼接上下文 → LLM 生成答案。
- **强项**：实现简单、生态成熟（向量库工具链齐全）、天然适配非结构化文本问答与语义搜索。
- **短板**：切块割裂上下文、多跳/关系推理弱、检索不到就容易答偏（垃圾进、垃圾出）。
- **典型场景**：文档/制度问答、客服知识库、语义检索。

### 2. KAG —— 知识增强生成（Knowledge Augmented Generation）

- **一句话定位**：在检索之上叠加*知识图谱与逻辑推理*，让答案"可推理、可溯源"。
- **核心做法**：以实体—关系图谱承载结构化知识，与向量检索互补，支持多跳推理与证据链追溯。
- **强项**：处理关系型/多跳问题更强、答案可解释可溯源、结构化知识表达清晰。
- **短板**：图谱构建与维护成本高、需要领域 schema 与持续治理、工程复杂度上升。
- **典型场景**：企业关系型知识问答、金融/医疗等对可解释性要求高的领域。

### 3. OAG —— 本体增强生成（Ontology-Augmented Generation）

- **一句话定位**：用*本体（概念、属性、约束、公理）*为知识建"骨架"，让语义形式化、可推理、可复用。
- **核心做法**：先用本体定义概念层次与关系约束（如 RDF/OWL 类建模思路），为图谱与检索提供统一语义层。
- **强项**：语义一致性强、支持形式化推理、跨系统/跨团队复用性好，是图谱的"上层规则"。
- **短板**：建模门槛高、依赖领域专家、落地周期长、对生成的增强是间接的。
- **典型场景**：医疗、工业、监管等需要强语义一致性与合规推理的行业。

### 三句话记住三者关系

1. **RAG 解决"找得到"** —— 快速把外部知识接进来。
2. **KAG 解决"理得清"** —— 把关系理成图谱，能多跳、能溯源。
3. **OAG 解决"想得通"** —— 用本体定义规则，语义一致、可推理、可复用。
4. **演进路径**：RAG → KAG → OAG，逐层增强、也可组合使用（详见 PPT 第 12–13 页与报告结论）。

## 三、听众提问与应答（Q&A）

**Q1：我们团队小、人手有限，该选哪个范式？**
A：直接从 **RAG** 起步。RAG 工程最成熟、上手最快，用现成向量库就能跑通闭环，投入产出比最高。KAG/OAG 的图谱与本体建设都需要持续的领域投入，建议先验证业务价值、确有"多跳推理/强可解释/强语义一致"的刚需时再升级。结论与报告一致：**先跑通、再增强**。

**Q2：我们已经有向量库了，要不要马上上 KAG？**
A：不必"一步到位"。既然已有向量库，说明 RAG 底座已经在了；先评估现有 RAG 是否真的卡在**关系型/多跳问题**或**答案不可溯源**上。若确实如此，KAG 的价值是把图谱与向量检索互补，解决多跳与可解释；若当前问题大多是单跳文本问答，改造收益有限。建议按需增强，而不是为了技术而技术。

**Q3：RAG 已经够用了，上 KAG/OAG 会不会是过度设计？**
A：有可能，关键看问题复杂度与合规要求。RAG 强在"找得到"，单跳文档问答、语义搜索用 RAG 就好；只有当业务需要**多跳推理、证据链溯源**（→KAG）或**强语义一致性、形式化合规推理**（→OAG）时，重投入才划算。选型应"由问题驱动"，而非由技术栈驱动。

**Q4：OAG 和 KAG 是什么关系？应该先做图谱还是先做本体？**
A：二者是**分层协作**而非替代关系。本体（OAG）是知识的"骨架/规则层"，定义概念、属性与约束；知识图谱（KAG）是这些概念与关系的"实例化"承载层。若领域语义复杂、需要跨系统一致，建议**先有本体再做图谱**，避免图谱建成后语义不统一；若只是关系查询，可先做轻量图谱。整体仍是 RAG→KAG→OAG 的逐层增强路径。

**Q5：三个范式能不能组合使用？该怎么落地？**
A：可以，而且推荐组合。典型组合是：**OAG 提供统一 schema 与规则 → KAG 承载图谱与多跳检索 → RAG 负责快速向量召回**，各取所长。落地建议分步走：先把 RAG 跑通形成可用闭环，出现多跳/可解释诉求时引入 KAG，需要强语义一致与合规推理时再补 OAG。这与报告的"演进+可组合"结论保持一致。

**Q6（备用）：怎么判断增强是否真的有效？**
A：围绕业务指标做验证：答案准确率、是否需要人工兜底、多跳/复杂问题的覆盖度、可解释与溯源是否满足合规要求。建议在小范围场景先做对照验证，用真实业务问题集检验，再决定是否扩大投入——不做无依据的规模扩张。
