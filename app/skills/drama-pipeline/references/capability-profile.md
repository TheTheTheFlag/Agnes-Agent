# media.py 能力档案（Capability Profile）

> **为什么建这个文件**：外部 skill（doublesq97-ui `tool-adapters.md`）列了一份 12 项
> 「通道能力核实清单」，但**明文拒绝写入任何实测值**（`:7`「本文件刻意不含易变参数」），
> 只有一个装饰性的 `last_verified: 2026-07-14`。
>
> 我们采纳它的**字段清单**，但**不采纳它的自我设限**——
> 因为「永不写死」= 主动丢弃全部可执行知识，实践中只会退化成「凭感觉试」。
> 我们的做法：**写死实测值 + 标验证日期 + 标失效条件 + 标未验证项**。
>
> **本文件是通道知识的唯一落点。** 新增能力先改这里，再改 `render-contracts.md`，
> 不要把参数散落在各文件里——那正是外部 skill「承诺 > 实现」的成因。

## 0. 字段规范

每个能力项必带四要素，缺一不予登记：

| 字段 | 含义 |
|---|---|
| **状态** | `已验证`（有实测证据）/ `推测`（合理但未测）/ `未知`（没试过） |
| **验证日期** | 最后一次实测的日期。`未知` 项写 `—` |
| **证据** | 跑过的命令 / 观察到的产物 / 日志片段 |
| **失效条件** | 什么情况下这条结论不再可信（换模型 / 换服务版本 / 换配额） |

> **`状态=推测` 的项不许写成禁令。** 只能写成「默认这样，建议实测」。

> ⚠️ **`--ref 语义角色分离` 这一项是本档案里最重要的 `未知`。**
> 我们在帧词里写「ref1 控制脸、ref2 控制服装、不得引入背景」，
> 但**从没验证过模型是否真的按这个分工执行**。
> **验证方法（低成本）**：同一角色 2 张 ref，其中一张带明显背景；
> 帧词写「严格参照 ref1 的面部，背景沿用 [SCENE] 段描述，不参照任何 ref 的背景」，
> 出图后看是否带进 ref 的背景。带进 = 不遵守分离；未带进 = 遵守。
> 结论直接决定我们的 ref 槽位三字段是**真机制**还是**自我安慰**。

### 1.2 `video`（出视频）

**先读这一段，否则参数会用错地方。** 视频有**两条互斥的参数通路**，由模型名决定
（`media.py` 以 `is_flash = "flash" in args.model` 分流）：

| | **flash 通路** | **非 flash 通路** |
|---|---|---|
| 模型 | `agnes-video-2.5-flash` | **`agnes-video-v2.0`（当前默认）** |
| `mode` 取值 | `text` / `keyframe` / `reference` | `ti2vid` / `img2vid` / `keyframes` |
| 时长参数 | `--duration` → `body["seconds"]` | `--duration` → `body["num_frames"]` |
| `--width/--height` | ❌ **静默丢弃** | ✅ 生效 |
| `--fps` / `--frames` | ❌ 静默丢弃 | ✅ 生效 |
| `--seed` | ✅ | ✅ |
| `--negative-prompt` | ✅ | ✅ |
| `--keyframes` 数量 | **必须 ≥2**，否则 `SystemExit` | 不限 |
| `--steps` | 后端不支持，传了只打印警告并忽略 | 同 |

> ⚠️ **`--width/--height` 在 flash 通路上是静默丢弃，不报错。**
> 我们一直在传 1280×720 —— 之所以生效，是因为当前默认模型是**非 flash** 的
> `agnes-video-v2.0`。**一旦把模型换成 flash，分辨率注入会无声失效。**
> 换模型 = 换一整套参数语义，不是改个字符串。

| 能力 | 状态 | 验证日期 | 证据 | 失效条件 |
|---|---|---|---|---|
| **duration 档位 = {3,5,10,18}** | 已验证 | 2026-09-28 | `VIDEO_PRESETS = {3:81, 5:121, 10:241, 18:441}`（`media.py:54`） | — |
| **名义时长 ≠ 实际时长** | 已验证 | 2026-09-28 | `actual = num_frames / 24`。3s→**3.375s(+12.5%)**、5s→5.042s、10s→10.042s、18s→18.375s | 换 fps |
| **`--frames` 可绕开档位** | 已验证（可传，未实测产出） | 2026-09-28 | 上限 441，须满足 `(n-1)%8==0`。**15s = `--frames 361`** | 后端改上限 |
| `--width/--height` 注入 | 已验证 | 2026-09-28 | 传 1280×720 → **模型原生落盘 1280×704** | 换 flash 模型即失效 |
| `--negative-prompt` | **已验证存在，从未用过** | 2026-09-28 | `media.py:459` 定义，`:376-377` 注入 `body["negative_prompt"]`（在 flash/非 flash 分流**之后**，两条通路都生效） | — |
| `--seed` | **已验证存在，从未用过** | 2026-09-28 | `media.py:460`；flash 走 `body["seed"]`，非 flash 同 | — |
| `--dry-run` | **已验证存在，从未用过** | 2026-09-28 | `media.py:305/390/444/467` 打印将发送的请求体后 `return 0` | — |
| `--mode` 显式指定 | 已验证存在，从未用过 | 2026-09-28 | `media.py:337-345` | — |
| `--fps` | 已验证存在（仅非 flash） | 2026-09-28 | `media.py:456`，1-60 | — |
| `--steps` | **禁传** | 2026-09-28 | `media.py:378`：后端不支持，传了只 `print` 警告并忽略 | — |
| 模型 A/B（4 个模型 0 次对比） | **未测** | — | `agnes-image-2.5-flash` / `agnes-image-2.0-flash` / `agnes-video-v2.0` / `agnes-video-2.5-flash` | — |
| 画面内文字可控性 | 推测差 | — | 禁令写进 prompt，实测仍偶有字。**`--negative-prompt` 可能改善，待测** | — |
| 口型同步 | 未知 | — | 我们已用「台词走画外 + 反应镜」规避 | — |
| 参考视频输入 | **不存在** | 2026-09-28 | `add_argument` 全量（`:431-486`）中**无任何参考视频参数**。外部 skill 声称有的功能，我们通道没有 | — |
| 返回音轨 | 已验证：默认有模型音轨 | 2026-09-28 / **2026-09-29 反转** | 默认**保留**作为交付配音（自带配音），不再 `-an` | `NO_AUDIO=1` 才去音轨 |
| `NO_AUDIO=1` 去音轨 | 已验证（原 `KEEP_AUDIO=1` 机制反转） | 2026-09-29 | 个别段发音严重跑偏时显式弃音轨，QA 反向验收无 audio | — |

> **`--width/--height` 不保证输出等于请求值**（1280×720 → 1280×704）。
> 所以机检的分辨率判据是**比例容差 0.05**，不是精确等于。**记成「等于」会误杀全部产物。**

> **`--negative-prompt` 是本次探测最大的收获**：我们**全部**禁令
> （禁止字幕/文字/水印、禁止面部漂移、禁止服装变化、禁止无关角色乱入、禁止角色数量变化）
> 至今都写进 prompt 正文当否定句。段视频有独立负向字段却没用过。
> ⚠️ **但关键帧出图（`image` 子命令）没有这个参数**（`:431-444` 无 `--negative-prompt`），
> 只能试 `--extra '{"negative_prompt":"..."}'`（`:442` 允许，`:381` 只填 `body` 里没有的键）——
> **后端是否吃这个字段，未验证**。所以「帧词用正文、视频词用 `--negative-prompt`」
> 是当前最优分工，**别把它写成「出图也能用负向字段」**。

## 2. 显式未知清单（按优先级排队实测）

| 优先 | 项 | 为什么值得测 | 成本 | 若为「是」的收益 |
|---|---|---|---|---|
| **高** | `--ref` 语义角色分离 | 决定 ref 槽位三字段是真机制还是自我安慰 | 1 次出图 | ref 纪律从「声明」升级为「可执行分工」 |
| **高** | negative prompt 独立字段 | 我们所有禁令目前都塞在正文里当否定句 | 0（先看 `media.py --help`） | 禁令从「祈使句」变「硬条件」，可能直接治好重复人 |
| 中 | 15s 时长档 | 段时长表可能多一档，节奏自由度提升 | 1 次出视频 | 3/5/10/18 → +15 |
| 中 | `--seed` 存在性与效果 | 同 prompt 复现能力，A/B 对比实验的基础 | 0（先 `--help`） | 失败重试不必靠运气 |
| 低 | ref 数量上限实测 | 我们已硬禁 >2，实测意义不大 | 8 次出图 | 低（已被规则覆盖） |
| 低 | 局部重绘 | 手/脸修图可能比整帧重出便宜 | 1 次 | 中（但整帧重出也就几分钟） |

> **先做 0 成本的**：negative prompt 字段与 `--seed` 只要看一眼 `media.py --help`。
> 一次 `ssh` 就能省掉后面所有猜测。**「先看 help 再讨论」应该成为反射。**

- 每次实测后**同时**改三处：本文件（能力值）、`agnes-service-ops.md`（操作步骤）、
  案例表（`skill-optimization-loop.md`，记这次测出了什么、之前错在哪）。

## 5. 风格字段规范（visual_styles.json 结构，2026-09-28 补自 zhaihao118）

zhaihao118 生产仓的 `visual_styles.json` 定义了 10 个风格的完整摄影机链字段，
**每个风格必须包含以下字段**（我们的 STYLE-11 次世代国漫 CG 参照此结构补充）：

| 字段 | 类型 | 说明 | STYLE-11 示例值 |
|------|------|------|----------------|
| `id` | int | 风格编号（1-based） | `11` |
| `name` | string | 英文名（英文提示词用） | `"Next-Gen CN Anime CG"` |
| `name_cn` | string | 中文名 | `"次世代国漫 CG"` |
| `camera` | string | 摄影机/机身 | `"ARRI ALEXA Mini LF"` |
| `film_stock` | string | 胶片/传感器 | `"Digital X-OCN"` |
| `filter` | string | 滤镜组合 | `"Pro Mist 1/8, Soft Glow"` |
| `focal_length` | string | 主用焦距 | `"35mm / 50mm"` |
| `aperture` | string | 主用光圈 | `"f/2.0"` |
| `prompt_suffix` | string | 追加到所有 ai_image_prompt 末尾的风格描述 | `"次世代国漫 3D CG 画风，顶尖国产 3D 建模，分层布料与物理衣摆，细腻发丝根根烘焙，电影级渲染光影，玄幻质感与高级感"` |

**字段来源与注入路径**：

```
visual_styles.json → metadata.json (style_id + prompt_suffix)
                    → 所有 out_image/out_video 调用自动拼入 prompt_suffix
                    → 投喂稿 [画幅风格] 段引用 style_id
```

> ⚠️ **我们的 STYLE-11 目前只有文本名，缺 camera/film_stock/filter/focal_length/aperture 字段。**
> 这是当前视觉风格管理的最短板，建议下一步补全。
