# 渲染链路契约（关键帧 → 视频 → 拼接）

> 本文件是渲染层的**唯一权威**。每条铁律都带「验证条件 / 失效条件」两字段——
> 没标验证条件的规则不许写成绝对禁令（2026-09-28 借鉴 zenstory `production-quality-gates.md` L78：
> 不把某模型的小样本表现套到所有同轨模型上）。

## 0. 规则分级（2026-09-28 新增，决定哪条能阻断）

| 级别 | 含义 | 能否阻断机检 |
|---|---|---|
| `structural_invariant` | 可机械证明的硬事实 | **能**，红了必须停 |
| `reviewed_invariant` | 需引用证据判断 | 不能自动停，人工判 |
| `craft_default` | 默认做法，允许说明理由后覆盖 | 不能，只 warn |
| `taste_option` | 口味 | **不得单独成为质量缺陷** |

铁律：所有 `qa_manifest.sh` / `qa_videos.sh` / `validate_prompt.py` 的红项，必须是
`structural_invariant`。`craft_default` 只能 warn。

## 1. 画幅锁（16:9 或 9:16，用户指定）

### 1.1 横屏 16:9（默认路径）
- 关键帧图必须按目标画幅生成：16:9 → `--ratio 16:9`（站点 2624×1472）。
- 视频侧用工具驱动注入 `--width 1280 --height 720`。
- **驱动注入在 `tools_deliver/gen_kzqs_videos.py`（含 `--width 1280 --height 720`），
  stage-kzqs 下的旧副本没有，渲染必须用 tools_deliver 版。**
- ⚠️ **实测口径差异（`structural_invariant`）**：模型原生按 16:9 出 1280×704（1.818），
  归一化需等比缩放 + 垂直 pad 至 1280×720。**QA 容差 0.05 覆盖 1.818**，
  但**报告与交付话术必须写实际交付分辨率，不得混用 704/720**。

### 1.2 竖屏 9:16 —— 禁止 pad / 禁止直接裁（2026-09-28 新增）
- `craft_default`：**9:16 版本不是 16:9 的 pad/crop 派生**。
  - `pad` 出来 68% 是黑边（1280×720 缩到 720×405 塞进 720×1280，有效画面仅 31.6%）；
  - `crop` 居中裁会切掉对话段 50% 宽度，两人镜必切掉一个人。
- **正确做法**：关键帧按 `--ratio 9:16` 重出 + 段视频按 `--width 672 --height 1152` 重渲，
  成本按横版 ×2 计入预算。
- 时间/预算不足时：**明确对用户说明只交付横版，不要交黑边片**。
- **安全区**（`craft_default`，2026-09-28 补，抄自 doublesq97-ui `cinematography:72`）：
  9:16 重新出图时，帧词 `[CAMERA]` 段须加
  「人物面部与双手、交互道具、运动落点均不贴近上下边缘，重要元素保持在画面中部 80% 区域内」。
  - 竖屏上下裁切是不可逆的：**脸被切掉就只能重出**（成本 ×1，不比横版重出的 ×2 便宜太多）。
  - 字幕/文字若将来上，一律进安全区；但本链路**不烧字幕**（§7），此条只管画面内容。
  - ⚠️ 这条**只对 9:16 成立**。16:9 横屏不写「安全区」（写了会诱导模型做上下留白构图）。

### 1.3 横屏构图三条（`craft_default`，16:9 专项）
1. **构图三件套**（帧词必带）：`画面左侧 1/3 …` / `右侧 1/3 …` / `两者之间保留负空间`。
2. **群戏写空间层级**「A 前 B 中 C 后」，**禁止「三人并排站立」**。
3. **景别分工**：双人/过肩/前后景承担叙事；特写只留给证据、认知转折、反应。
   横屏全景要靠纵深（门框/遮挡/前后）立关系，不靠横向铺开。

## 2. manifest 契约（rebuild_manifest.sh <EP> 从投喂稿重建）

```json
{ "episode": "E01", "project_dir": "<项目根绝对路径>",
  "segments": [ { "seg": "E01-01", "prompt": "…", "duration": 10,
                  "keyframes": ["<kf1 绝对路径>", "<kf2 绝对路径>"] } ] }
```

- keyframes 按文件名序取 kf1/kf2（kf3 可选）；每段 ≥2 帧，否则驱动降级 img2vid。
- md 修订后必须重跑 `rebuild_manifest.sh <EP>` 再渲染，避免二次创作与 manifest 不同步。
- **文件名自然序 == 段序**（`structural_invariant`，2026-09-28 补，防回归）：
  段目录必须命名为 `E01-01 … E01-16`（**两位零填充**），使 `ls` / glob 的字典序 == 段序。
  - 事故记录：`${EP}-0*` 这类 glob 会漏掉 `-10` ~ `-16`（`0*` 只匹配一位前缀），
    `concat_episodes.sh` 因此只拼了 9/12 段却 `exit 0`。已改为**枚举后与 manifest 对账**。
  - **规矩**：段目录**只允许**按 manifest 里的 `seg` 字段枚举，**禁止**用通配符猜段集合。
  - 资产变体同理：`chr-001` / `chr-001-look-002` 零填充，**禁止** `CHR-02b` 式无状态语义编号。
- **refs 不在 manifest 里**，在 `投喂稿/kf_plan.json`（`segments[].refs`）——渲染读 manifest，
  出图读 kf_plan。两者用途不同，勿混。

## 2.1 资产状态词表（7 态，`reviewed_invariant`）

`assets/manifest.json` 的 `status` 字段只允许这 7 个值（2026-09-28 统一，
抄自 doublesq97-ui `continuity-assets:13-21`；**注意同仓 `roles-and-handoffs:27-34`
只写 6 态漏了 `rejected`——我们取 7 态版**）：

| 态 | 含义 | 能否入 ref |
|---|---|---|
| `proposal` | 提案，未出图或未审 | ❌ |
| `selected` | 已选中待出图 | ❌ |
| `locked` | **已锁定**，用户确认过 | ⚠️ 锁定≠可入模（§4.3 资产禁令照常） |
| `in-production` | 正在生成/渲染 | ❌ |
| `rejected` | **被否决** | ❌ 永不复用 |
| `superseded` | **被新版取代** | ❌ 不静默替换，登记 `relationships` |
| `blocked` | 被上游阻塞 | ❌ |

- **「工具返回成功」不等于「资产完成」**（`continuity-assets:23`）——
  状态只能由**用户审核**推到 `locked`，不由任务返回值决定。
- 台账、《资产图册.md》、《剧组产出册.md》三处用同一套词，不许各写各的。

## 4. 关键帧出图（最高风险环节，2026-09-28 大幅重写）

### 4.1 ref 槽位契约（`structural_invariant`，直接治「人物重复」）

**每张 ref 必须声明三字段，并必须被翻译进 prompt 正文**——`media.py` 只把文件丢给模型，
三字段不进 prompt 等于没写。

`kf_plan.json` 每段 refs 逐张写：
```
<绝对路径>《<中文名>》（用途：身份|造型状态|地理|构图|尺度|效果；
                   控制：<范围>；不得控制：<范围>）
```
顺序即 `--ref` 传入顺序。

**固定搭配（三条，不可省）**：
| ref 类型 | 用途 | 控制 | **不得控制** |
|---|---|---|---|
| 角色净版立绘 | 身份 | 脸型、体态、识别标记、本集不变造型 | **姿势、构图、背景、光线、其他角色、人数** |
| 场景图 | 地理 | 入口、固定锚点、方位关系 | **人物、人数、剧情状态** |
| 道具图 | 造型状态 | 形制、配色、当前开关/亮灭态 | 持有者、背景 |

**落到 prompt 正文**（`--ref` 顺序 = 编号顺序）：
```
参考图1《赤焰立绘》：仅用于人物身份与本集造型；不参照其姿势、背景、光线与画面构图。
参考图2《天穹城空景》：仅用于广场入口、纪念碑方位与地平关系；不参照其中任何人物，人物数量由[人数]段决定。
```

### 4.2 ref 数量纪律（`structural_invariant`）

**适用范围：关键帧出图（`media.py image --ref`）。** 视频段的 `--keyframes` 是另一层，不受本表约束。

| 场景 | ref 数 | 依据 |
|---|---|---|
| 单人镜 | **1**（该角色净版立绘） | 1 ref 一致性 ~95% |
| 双人镜 | **2**（两张单人立绘） | 2 ref ~80% 可接受 |
| **3 人及以上** | **1**（视觉主角），其余进 `[BACKGROUND]` 段并**强制剪影/虚化** | 3+ ref 一致性 <50% |
| **空镜 / 环境 / 道具特写** | **0**（CHR、SCN、PRP 一律不挂） | 挂了模型就有充分理由把人塞进画面，且常塞两次；地理/道具信息走 `[SCENE]` 段文字，见 §4.3 |
| **多人同框 + 强地理依赖** | 仍是 **1~2**（宁可少挂） | ref 不是信息通道，是身份锚。地理写在文字里成本为零、精度更高 |

- ref 顺序按**视觉重要性**排，不按剧情先后（第 1 张权重最强，第 3+ 急剧衰减）。
- **一张图只承担一件事**。禁止「全参考」：一张 ref 既当身份又当地理。

> **2026-09-28 一致性修订**：本表旧版「空镜行」写的是「0 张 CHR ref（可挂 SCN/PRP）」，
> 与 §4.9「场景/道具信息一律走 `[SCENE]` 段文字，不挂 ref」以及 §4.3 的机检
> （按 ref 父目录 `assets/` 判定，**SCN/PRP 全在 `assets/` 下**）三方矛盾。
> **机检早已站队「一律不挂」**，本表现已统一为 **0**。
> 要放宽「单视角场景图可作 ref」属于需实测的新决策，本版明确不做。

### 4.3 资产禁令（`structural_invariant`，`qa_manifest.sh` 硬阻断）

> **禁止任何资产图作为关键帧 `--ref` 入模——不只是资产板，是全部。**
> 资产图（角色板 / 角色立绘 / 场景图 / 场景板 / 道具图 / 道具板）仅供人看与审核台比对。

- 资产板（含 4 视图 / 多宫格 / 多姿态 / 多变体）禁入模的理由：模型把
  「一个空间被切成 N 个视角面板」与「一个人被切成 N 个姿态」在图像统计上同构，
  重复出图是**必然结果而非概率问题**。
  已在《花语战歌》实测：12/12 段的 refs 末尾挂了 4 视图场景资产板 `SCN-01.png` → 人物重复。
- **为什么连单视角图也禁**（2026-09-28 明确）：门禁按 **ref 的父目录是否为 `assets/`** 判定，
  而本链路所有资产图都在 `assets/` 下。若只禁「多格图」，规则会依赖机检去数图内分格数——
  那是图像内容判断，我们没有可靠自动判据。**按目录判定是唯一可机械证明的口径。**
- 机检实现（`scripts/qa_manifest.sh`）：ref 的**父目录名为 `assets`**，
  或文件名匹配 `sheet|4view|4-view|board|multi|视图|资产板` → FAIL。
- 另检：同一段内同一 ref 重复挂载 → FAIL；单段 ref 数 >2 → FAIL。
- **代价是资产图不参与生成**——这意味着角色身份**只能**由净版立绘承担，
  而净版立绘同样在 `assets/` 下。**因此本链路的实际做法是：净版立绘由 `kf_refs/`
  等 ref 专用目录承载**（不进 `assets/`），资产板与资产台账留在 `assets/`。
  `qa_manifest.sh` 按 `assets/` 判定正是为此设计——**改目录结构前先想清楚这层。**

### 4.4 角色立绘 ref 的出图要求（`craft_default`）

- **中性平光 + 单色纯背景**。禁止戏剧光/边缘光/体积光打在 ref 上——
  模型会把 ref 的阴影误判为颧骨/眉骨，导致下游关键帧面部结构漂移。
- 画面中 1 个人物，人物占幅 <50%，大留白。
- 同一 CHR 的多年龄段/多服装资产，**一律以已有资产图为 `--ref` 走 `assets/regenerate`
  改词重出，禁止作为独立任务新出图**——既省 credit 又保脸一致。

### 4.5 帧词九段式结构（`craft_default`，有序配方）

帧词按**显式标签分段**，每段独立一行，模型按段处理、信息不混：

```
[画幅]      16:9 横屏（用户指定 9:16 则改）
[人数]      画面中仅有 N 人：A、B、C，每人只出现一次…   ← 前置，不是末尾
[CHARACTER] A，B（身份只来自参考图1/2，不重描五官发色服装）
[BACKGROUND] 其余角色/背景人物一律剪影或虚化处理
[SCENE]     场景文字锁定（地理/材质/锚点/光向）
[CAMERA]    景别·角度·机位高度·轴侧
[LIGHT]     光向 + 质感 + 补光声明
[STYLE]     画风档（逐字并入）
[EXCLUDE]   本帧可能出现的矛盾或漂移
```

**顺序不可调换**：`[画幅]` 开头权重最高；`[人数]` 必须紧随其后（`reviewed_invariant`）。

**9 项配方的完整写法、纵深三段、焦点层级、与上一镜相同句**
→ 见 `references/keyframe-craft.md`。

### 4.6 人数约束句（`structural_invariant`）

**从帧词末尾移到 `[人数]` 段并前置**，同时末尾 `[EXCLUDE]` 保留一条：

```
[人数] 画面中仅有 4 人：赤焰、冰璃、焰心、维瑟拉，每人只出现一次，一人一实体。
[EXCLUDE] 禁止任何角色重复出现、禁止背景路人、禁止围观群众、禁止同角色多视角并列、
           禁止分屏拼接、禁止镜像倒影分身。
exactly 4 characters in one single unified shot, one instance of each, no duplicated
characters, no repeated faces, no extra people, no crowd, no background figures,
no split screen, no collage, no multiple views, no mirror or reflection duplicates.
```

> **为什么必须前置**（2026-09-28 实测）：帧词末尾的约束是**后置文本**，
> 权重打不过前置的**图像条件**（N 张 ref）。末尾句只能约束「模型自己多画的人」，
> 约束不了「ref 里本来就有的面板/人群」。

### 4.7 帧词禁令（三条 `structural_invariant`）

1. **禁止重描角色外貌**：五官、发色、瞳色、体型、服装细节一律不许出现在帧词里。
   身份**只来自 ref**。重描等于让模型按文字重画 → 产出「像 ref 但不是 ref」的新人。
   （我们现有的「画面中人物严格沿用参考图中的面貌与服饰」方向正确但力度不够，
   需配本条禁令 + 机检。）
   - **唯一例外口（2026-09-28 显式开洞）**：允许写该角色的**标志色**一个颜色词
     （例：`赤焰身着标志性的赤红色外袍`）。机检白名单**只放行颜色词**。
     为什么开这个口：颜色是模型区分「这是两个人」的**最稳信号**；
     而「禁止点名未出场角色」+ 2 人同框时，模型唯一能用的区分手段被我们掐掉了 →
     两人被画成同类构图 → 重复人。配套前提是**剧本角色清单已分配互补/不重叠标志色**
     + **剪影差异**（`SKILL.md` §2），否则随机写颜色等于没开。
   - 边界：**只许颜色，不许五官/发色/瞳色/体型/服装结构/纹理**。开了口不等于开了闸。
2. **禁止未出场角色被点名**：帧词里未出场的角色**一个名字都不许出现**。
   点名一个本镜不需要的人 = 凭空授权模型画他。
3. **禁止动作动词**（2026-09-27 铁律，保留）：`疾走/走出/目送/递出/接住/起身/按肩/塞进/回头/
   转身走开/正要消失…`。全链机检：`动作动词残留: 0`。

> 另注（`reviewed_invariant`）：动词黑名单是**结果层**规则，管不到无动词的时序矛盾
> （如「并肩坐下」+「走向天台」= 一坐一站被写成两人）。根因是**两个时刻被拼进同一 prompt**，
> 修法是单一时刻·单一姿态·自洽定格，不是加词。

### 4.8 帧词字数与并发（`craft_default`，系数为推测需实测校准）

| 帧词字数 | 出图并发 | 依据 |
|---|---|---|
| ≤1200 字 | ≤4 | 默认 |
| 1200-1500 字 | **降到 1-2** | 长 prompt + 并发在同类接口上会 100% 失败 |
| >1600 字 | **阻断，重写** | 硬上限位 |

- 建议用「**删句测试**」自查：删掉任意一句，如果画面没有变得更不确定，那句就是多的。
- ⚠️ **禁止用「增加形容词」回应重复缺陷**：在同一条提示词上叠加
  「高质量、避免变形、保持一致」，既没改变任何可执行事实，又让下一次失败失去可比性。
  重复缺陷的正确处置是**换层级**（拆镜 / 减 ref / 改结构），见 `skill-optimization-loop.md` §处置五选。

### 4.9 关键帧出图模板（已修正——原稿此处的 `[--ref <SCN>]` 是 bug 源头）

```bash
  --ref <视觉主角净版立绘>
```

**场景/道具信息一律走 `[SCENE]` 段文字，不挂 ref**（与 §4.2 空镜行、§4.3 门禁三方一致）。

### 4.10 帧词静态化铁律（2026-09-27，保留）

- 帧词必须**独立书写**（kf1/kf2 各一份），**禁止复用视频场景 prompt**
  （视频 prompt 是动态分镜脚本：时间码/声音/台词，不是定格画面。视频词写法见
  `references/video-prompt-craft.md`）。
- 站位关系并入 `[CHARACTER]` 句，**不设独立「站位」段落**。
- 结尾/任一段禁止把段首段末两个不同时刻的状态拼进同一 prompt。
- kf1/kf2 同段内差异上限：同场景、同站位、同光线、同道具，仅姿态或景别微变。
  **两端差异越大，模型插值越自由，中间越不可控**——若两端之间的动作构成本段存在的理由
  （路径即戏），应拆镜，而不是交给插值。
- **「独立书写」扩展到一切批量出图**（2026-09-28 补）：资产多视角、4 View、多年龄段、
  多服装批量出图时，**每张图的 prompt 必须完整独立写全**，
  **禁止「同上」「其余一样处理」「保持不变」「其他不变」「参考原图」这类概括与空话**。

### 4.11 形象变更回炉路径（2026-09-28 新增，唯一允许的「往回走」）

**触发条件**（在关键帧或渲染阶段发现任一即触发）：
换装 / 发型变化 / 受伤毁容 / 年龄阶段变化 / 身份伪装 / 盔甲制服礼服等**形象变更**。

**回炉流程（顺序不可跳）**：
1. **停止该段后续动作**（该段不渲影；`pipe_render.py` 暂停该段，其余段照旧）。
2. **回资产阶段**：以原资产图作 `--ref` 走 `POST /api/drama-review/assets/regenerate`
   改词重出对应阶段的资产图。**禁止沿用旧资产图硬套新造型**，也**禁止**把新造型
   只写进帧词（那就变成「像旧 ref 但不是旧 ref 的新人」）。
3. 新资产图登记 `assets/manifest.json`。变体 ID 走 `{类型}-{ID}-{状态或变体}[-vNN]`
   （`chr-002-look-002` / `scene-014-state-night-rain`），**旧式 `CHR-02b` 保留为别名**写进
   manifest `aliases` 字段——**不破坏存量引用**。新登记必须写 `controls` / `not_controls`（§4.1）。
4. **旧版本标 `superseded` 并登记 `relationships`**（`derived_from` / `supersedes` / `used_by`），
   **不静默替换**。状态词表统一 7 态（§2）：`proposal / selected / locked /
   in-production / rejected / superseded / blocked`。
5. **资产审核确认**（8081 工作台「短剧审核」→ 资产审核）——**未经用户确认不得继续**。
6. **写影响面清单**（P0，此前此步只说「更新受影响的帧词」却没说怎么判断受影响）：
   ```
   变更资产：chr-002-look-002（supersedes chr-002-look-001）
   受影响段：E01-04 / E01-05 / E01-09
   需改 kf_plan.refs：E01-04[refs[0]]、E01-05[refs[0]]、E01-09[refs[0]]
   需改帧词段：[CHARACTER] 段（3 段）——其余段不动

   ```
   - **判据**：凡 `kf_plan.refs` 含该资产路径的段，**或**帧词 `[CHARACTER]` 段点名该角色的段，
     一律进清单。清单写完再动手，不许边改边发现还有漏的。
   - 清单必须落盘（回炉记录进台账），不是口头确认。
7. 更新 `kf_plan.json` 的 refs（换 ref 路径）与清单内受影响的帧词 `[CHARACTER]` 段。
8. 重出清单内受影响段的关键帧 → 重跑 `qa_manifest.sh`（refs 纯净度 + keyframes 存在性 + 禁用元素）。
9. 恢复逐段流水。

> **「登记衍生品来源关系」是硬要求**：任何下游产物（帧词 / 视频词 / 段视频 / 剪辑点）
> 都必须引用 canonical ID + 版本。派生出来的图（如裁切版/局部版）要登记 `derived_from`，
> 否则半年后没人知道那张图是谁的。

> **这是「十步顺序不可乱」的唯一例外**（`SKILL.md` §一）。其余任何情况都不许跳步。
> 另注：`sumeru-*` 剧本阶段的角色设定若与资产冲突，**以资产为准**——
> 剧本只定义「这个人是谁」，不定义「这个人长什么样」；形象**只在资产阶段定义一次**，

## 5. 视频驱动（逐段流水）

```bash
export AGENT_INTERNAL_TOKEN=$(cat /home/mirror/Agnes-Agent/data/internal_token)
python3 /home/mirror/Agnes-Agent/tools_deliver/gen_kzqs_videos.py <项目根>/投喂稿/<EP>/manifest.json <段号>
```

- 产物：`<项目根>/<段号>/<段号>.mp4`；日志 `<项目根>/video-run.log`。
- **逐段流水（2026-09-27 铁律）**：某段 kf1+kf2 出图齐即渲影该段，不等全量帧；两帧未齐不渲该段。
- **并行规则**：media.py 底层为「POST 建任务→轮询」异步模式（后端排队+自动重试），
  多段出图可并行（并发 ≤4，见 §4.8 字数联动）、帧齐多段渲影可并行（并发 ≤2）。
  唯一硬约束：同一段不得同时开两个任务；段内顺序 出帧→渲影。

### 5.0 视频词（段视频 prompt）—— 与帧词是**不同的层**

| | 帧词（kf1/kf2） | 视频词（段视频） |
|---|---|---|
| 形态 | 静态定格 | **动态分镜脚本**（时间拍 + 机位 + 动作 + 声音） |
| 时间轴 | ❌ 禁 | ✅ **必须**，各拍首尾相接，末拍终点 = 段 `duration` |
| 动作动词 | ❌ 禁 | ✅ 必须，且带**部位+幅度+速度** |
| 点名规则 | 禁点名未出场角色 | 禁代词、禁群体量词（点名即动作指代） |
| 工艺文件 | `keyframe-craft.md` | **`video-prompt-craft.md`** |

- **禁止互相整段复用**：帧词套到视频上 = 静帧漂移；视频词套到帧词上 = 两个时刻被拼进同一 prompt
  = 重复人（`skill-optimization-loop.md` 已沉淀的两个事故同型）。
- 每段视频词**必须重新声明**该集的世界底噪与调基调——每段是独立任务，模型不知道全集设定。
- 末尾固定禁令含**「同一角色在整段内只出现一次」**——运动插值中模型可能复制出「跟着动的人」。

### 5.1 超时分级（2026-09-28 新增，替换 99 小时空转）

原稿 `--timeout 356400`（≈99h）会在任务静默死亡时空转数天。改为：

| 阶段 | 建议超时 | 超时后动作 |
|---|---|---|
| 出图 | 300s | 先 `fetch` 确认一次 → 仍无 → 判 FAIL，写 `FAILED` 标记 |
| 视频 | 1800s | 同上 |
| 渲影 | 1800s | 同上 |

`fetch` 续查、**禁止重复建任务**（重复提交 = 付两次钱）。

### 5.2 静帧兜底（`craft_default`，强烈建议启用）

一段渲染失败不该让整集 concat 卡死。降级为静帧 zoompan（成本 0，可用性保留）：

```bash
ffmpeg -y -loop 1 -i "$KF" -t "$dur" -vf \
 "scale=1280:720:force_original_aspect_ratio=increase,crop=1280:720,\
zoompan=z='min(zoom+0.001,1.10)':d=$((dur*30)):x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':s=1280:720,\
setsar=1,fps=30" -c:v libx264 -crf 20 -pix_fmt yuv420p -an "$out"
```
落盘的段必须打 `STATIC_FALLBACK` 标记，concat 后在台账列明，**不得当作正常段交付而不告知**。

### 5.3 统一调色 + 段内淡入淡出（`craft_default`，成片感的最廉价来源）

各段来自不同任务，曝光/色温必然漂移。concat 前逐段统一：

```bash
-vf "eq=contrast=1.05:saturation=1.12:gamma=0.98,vignette=PI/5,fade=in:0:12,fade=out:$((FRAMES-12)):12"
```

### 5.4 段视频归一化（concat 前置步，2026-09-29 沉淀）

渲影产物必带两类系统性溢出，**不动手归一化 = 拼接/验收必破线**：

| 溢出 | 实测值 | 后果 |
|---|---|---|
| 画幅 | 模型原生 **1280×704**（1.818），非 1280×720 | 交付话术与实际不符；竖版/混流源不一致 |
| 时长 | 24fps 帧对齐，**18s 档实为 18.375s**（+0.375s/段） | 整片超 240s、concat 时长对账破 0.5s 容差 |

标准解法（本包 `scripts/normalize_segments.py`，幂等）：

```bash
python3 scripts/normalize_segments.py <项目根> [EP ...] [--workers N]
# 每段：scale=1280:720:force_original_aspect_ratio=decrease,pad=…,setsar=1
#      + -t <manifest 声明时长> + -an + libx264 crf18 preset medium +faststart
```

- **声明时长是唯一权威**：`-t <decl>` 裁掉帧对齐溢出；**不得**反过来改 manifest 迁就产物。
- **覆盖前备份**：`<R>/.review/pre_normalize/<seg>.mp4` + `INDEX.jsonl`（原路径 + sha256 + 时间）。
- **幂等**：已达标（1280×720 / ±0.05s / 无音轨）的段直接 `SKIP`，可安全重跑。
- 退出码 0=全 OK/SKIP，1=有 FAIL——FAIL 段**不得**进 concat。
- 顺序：渲影 → **归一化** → 统一调色（§5.3）→ concat（§6）。

## 7. 字幕边界（工程无字幕叠加，仅防模型画面内文字）

- **链路确认**：`gen_kzqs_videos.py` 与 `media.py` 均无 drawtext/overlay/.srt/.ass 等烧录逻辑，

## 8. 无配音契约（2026-09-27 新增，根治模型英文配音）

- **规则**：`gen_kzqs_videos.py` 渲染**永远不保留模型自带音轨**——段视频复制落盘后立即
  `ffmpeg -y -i dst -an -c:v copy` 去音轨，失败才保留原轨并记日志；禁止任何后续环节把模型音轨当成品交付。
- **根因**：模型原生配音偶发生成英文，人工挑段不可靠 → 从源头禁用模型音轨。
- **配音走向**：由 `scripts/local_tts.py` 从 SRT 生成中文配音，产出 `voice_mix.wav` 后按需混入成片。

  （`KEEP_AUDIO=1` 特例项目应含 `video,audio`）。

## 9. 成本与耗时台账（2026-09-28 新增）

**优化优先级：段数是唯一的大杠杆。** 实测参考（cyuanxv 案例，同类接口）：
资产迭代 ≈ 5% credit / 11% 时间；关键帧出图 ≈ 13% / 9%；**视频段 ≈ 83% / 67%**。

- 每集产出册必须登记：`关键帧 N 张 / 视频 M 段 / 重试 K 次 / 墙钟时长 T / 失败段列表 / credit 估算`。
- **预算闸门**：每集设 credit 上限 + **重试预算上限**。超限即停并上报，不得「自动重试直到成功」。
- **失败也扣费** → 同一输入连续原样重投 **≤2 次**，之后必须改内容或退回负责环节。
- 重渲必须声明 `changed_input`（prompt|reference|params）与 `preserve_set`；
  连续 2 次 `changed_input: "none"` → 拒绝执行并提示「原样重投不产生修复」。
