# 世界规则与禁用元素（World Rules）

> 6 份外部 skill 全部**没有**这一层（grep `无男性|架空|只有女性|all-female` → 0 命中）。
> 唯一沾边的是 `project-bible` 的「世界规则」自由文本块，**且没有任何门槛校验**。
> 所以本文件是**自建**，不是抄。
>
> **为什么必须建**：架空世界只有女性、剧内禁止任何男性角色/称谓/形象——
> 这类设定如果只停留在口头约定与剧本描述层，**必然在某一段的帧词里漏进来**。
> 而模型不区分「设定」与「描述」：你在帧词里写「她转头看向窗外的男爵」，模型就会画出来。
> **设定必须是可机检的。**

## 1. 规则三型

| 型 | 内容 | 机检 | 落点 |
|---|---|---|---|
| **世界不变量** | 本剧恒为真的事实（能力体系、物理规则、社会结构） | ❌ 不机检（无法从词面判定） | 剧本 `project-bible` §2 |
| **禁用元素** | 本剧**绝对不许出现**的人/物/词/形象 | ✅ **硬阻断** | 本文 §2 + `qa_manifest.sh` |
| **偏好元素** | 鼓励但非必需（构图、质感、节奏） | ❌ 只 warn | 本文 §4 |

**只有「禁用元素」能进机检。** 把偏好写成禁令会制造大量假红，三轮之后没人再看机检输出。

## 2. 禁用元素登记（`structural_invariant`）

`assets/manifest.json` 与投喂稿【强制禁止项】段各持一份，**以 `world_rules.json` 为准**。

### 2.2 扫描范围

| 文件 | 强制 | 说明 |
|---|---|---|
| `投喂稿/<EP>/投喂稿-<EP>.md` | ✅ | 【强制禁止项】段本身会**声明**禁用清单，会自我命中 → **跳过该段** |
| `投喂稿/kf_plan.json`（帧词） | ✅ | 最高优先级 |
| `投喂稿/<EP>/manifest.json`（视频词） | ✅ | |
| `assets/manifest.json`（资产 prompt） | ✅ | 场景/道具资产还须零人物（§3） |
| 《剧组产出册.md》/《资产图册.md》 | ❌ | 文档，允许描述「禁止出现男性」 |
| 剧本 `juben` | ❌ warn | 剧本是设定来源，允许出现「这个世界没有男人」这类描述 |

### 2.3 否定声明子句必须剔除（否则必然假阳性）

**这是实测踩到的坑，不是理论风险。**

我们的 4 张角色资产 prompt 都写着「…画面严禁出现男性…」，机检第一版把这 4 条
**全部判成违规**——因为「男性」确实出现在 prompt 里，但它是**禁令的宾语，不是画面内容**。

修法：扫描前按 `[。；;，,\n！!？?]` 切子句，**丢弃含否定标记的子句**。
默认否定标记 12 个：`严禁 / 禁止 / 不得 / 不出现 / 不含 / 没有 / 无任何 / 无人物 / 切勿 / 避免 / 不要 / 未出现`
（可在 `safe_overrides.negation_markers` 覆盖）。

| | 文本 | 判定 |
|---|---|---|
| ❌ 真违规 | `一名将军拔剑，她退后半步。` | **FAIL** |
| ✅ 禁令声明 | `画面严禁出现男性。` | 剔除子句，不判 |
| ✅ 语义安全 | `少女望向少女们` | 白名单放行 |

- **副作用要认**：含否定的小句被整句丢弃，可能漏掉真实内容
  （如「她没有看到那名将军」会整句跳过）。**接受这个漏报**——
  漏报一次可以事后人眼补，假阳性三次就没人再看机检输出了。
- **通用原则**：任何「扫描文本找禁用词」的机检，都必须先问
  **「这句话本身会不会合法地包含这个词？」**。会 → 必须有剔除规则。
  同型风险：查脏词时「不要出现脏话」这句本身带脏字。

## 3. 场景/道具资产图零人物（`reviewed_invariant`）

与 §2 的世界规则**独立**的第二条：

- 场景/道具资产图 prompt 固定收尾：
  `纯场景/道具资产，画面中无任何人物、无剪影人形、无倒影人形、无可辨识面孔。`
- 理由：场景资产图一旦含人形，它就是「凭空多一个人」的**现成素材**。
  虽然 §4.3 资产禁令让它们不进 ref，但人眼审核时会默认「这图里那个人是角色」→
  后续帧词/分镜里就会多出一个人。
- ⚠️ 机检只能扫 **prompt 文本**（扫图像内容需人眼），所以这条是 `reviewed_invariant`：
  落到人眼审核项，不落机检红项。

## 4. 偏好元素（`taste_option`，永不作为质量缺陷）

- 纵向空间分层：上文见「架空遗迹」「高塔俯瞰」——把架空感做进画面。
- 统一色调家族：本作偏好「冷蓝 + 炽焰橙」双极对比。
- 材质偏「金属 + 织物 + 石材」三件套。

## 5. 违反时的处置（**不是加词**）

机检报出禁用元素时，**不要**在提示词里加「禁止男性」——那只是把禁令变成了一条
模型可以忽略的否定句，而且会让下一轮失去可比性。

按 `skill-optimization-loop.md` §缺陷处置五选：

1. 查是不是**词表误伤**（该词是否进了 `safe_overrides`）
2. 查是不是**引用串了**（帧词/视频词是否误粘了剧本描述）
3. **换措辞**：该处本来想表达的东西，用不含禁用子串的方式重写
   （❌「男爵的军旗」→ ✅「霜华军团的军旗」——**改设定归属，不删信息**）
4. **删该处**（若该信息确实不属于本剧）
5. 确有创作需求（如剧本确有人类男性角色）→ **改设定，不改机检**；
   本剧设定已锁定为纯女性世界，所以这条路对本剧关闭。

> **第 3 条是关键**：多数「禁用词」其实来自**误归属**——把「男性/阳性」的世界观素材
> 顺手写进了别的势力的描述。**改归属比删句子更正确**，也更少损失信息。

## 6. 新剧如何建这份文件

1. 剧本阶段确定世界不变量，把**任何「不许出现」的东西**逐条列出来
   （人、物、形象、词、关系类型、生物类别）
2. 分类进 `banned_elements` 的四个子组（按需要增删子组）
3. **先在剧本上跑一遍**扫描，允许命中但必须逐条确认「这是设定描述，不是画面内容」
4. 冻结 `world_rules.json`，投喂稿与帧词阶段启用硬阻断
5. 每次新增禁用项 → 补 `safe_overrides` 反查（新增禁用词会不会误伤已有内容）
