# Skill 优化循环（复盘 → 沉淀 → 复核）

> 当任务暴露缺陷（用户反馈/机检不过/重复踩坑/交付翻车）或有更优做法时，按本循环改进 skill 本体，
> 让规则沉淀进权威文件，下次直接生效。

## 循环五步
1. **复盘定位根因**：先查档案（剧本 juben、投喂稿、manifest、`kf_plan.json`、生成器 `gen_*_kf.py` /
   `gen_kzqs_videos.py`、资产台账），用证据锁定病灶，不要凭表象猜。
   例：人物不一致 → 先查 `--ref` 引用了**哪几张图**（数量/是否资产板），再查帧词，
   而非直接「重生成整片」。
2. **最小修复或规则沉淀**：能局部修就不整片重做；
   根因是规则缺失/写死 → 把修法写成新规则/修订现有权威文件。
3. **改 skill 本体**：权威文件（`references/*`）+ 铁律块 + 目录树 + README 一处不漏；
   用户原稿/定稿文件逐字保留，只加作用域说明，不删改原文。
4. **复核残留**：`grep -rn` 旧锚词确认零残留；改完即生效（loader 实时扫描 .md，无需重启）。
5. **清理工具性残余**：.validate 目录、临时收集脚本、pscp 暂存文件等任务收尾清理。
   ⚠️ **备份件（`*.bak-*`）在任务确认稳定前不许删**——它们往往是唯一的好版本
   （实测：scp 静默失败留下 0 字节文件，`cp` 把备份好的 `qa_videos.sh` 覆盖成了空的）。

## 规则分级（决定哪条能阻断机检）

| 级别 | 含义 | 能否阻断 |
|---|---|---|
| `structural_invariant` | 可机械证明的硬事实 | **能**，红了必须停 |
| `reviewed_invariant` | 需引用证据判断 | 不能自动停，人工判 |
| `craft_default` | 默认做法，允许说明理由后覆盖 | 不能，只 warn |
| `taste_option` | 口味 | **不得单独成为质量缺陷** |

- 所有 `qa_manifest.sh` / `qa_videos.sh` / `validate_prompt.py` 的红项**必须是** `structural_invariant`。
- ⚠️ **没标验证条件的规则不许写成绝对禁令**——不把某模型的小样本表现套到所有同轨模型上。
  例：「3+ ref 一致性 <50%」是**已观测**数据，标 `reviewed_invariant` + 写明数据来源；
  「>1600 字必失败」是**推测**，标 `craft_default` + 写「需实测校准」。

## 缺陷处置五选（同一层级内换，不许叠形容词）

出图/出视频出现质量缺陷时，**按此顺序换层级**。禁止在同一条提示词上叠加
「高质量、避免变形、保持一致」——既没改变任何可执行事实，又让下一次失败失去可比性。

| 序 | 动作 | 何时用 |
|---|---|---|
| 1 | **查条件**：refs 数量/是否资产板/画幅/seed | 最高概率根因，先查 |
| 2 | **减条件**：拆掉一个 ref、去掉一段词 | 条件过载 |
| 3 | **换结构**：拆镜 / 改换景别机位 / 改换构图方案 | 结构性矛盾，词解决不了 |
| 4 | **加约束**：前置人数、加 `[EXCLUDE]` | 根因是「模型自己多画的」 |
| 5 | **退回负责环节**：换画风档 / 换资产 / 改剧本 | 上面都不成立 |

> **第 5 步与「禁降级」不是一回事**（2026-09-28 补）：禁的是**无声降级**——
> 工具失败后悄悄改用 T2I/T2V，那会丢掉参考图约束并破坏一致性，还让失败变得不可见。
> 显式换层级（拆镜 / 减 ref / 换结构）是允许的，但必须**声明改了什么**。
> 体现在审核台就是 `changed_input`（prompt\|reference\|params）+ `preserve_set`。

> 处置后仍失败 → 判定该构图在本模型上不可达，**记录并换方案**，
> 不要进入「再试一次原样重投」的循环（失败也扣费）。
> 重渲必须声明 `changed_input`（prompt|reference|params）与 `preserve_set`；
> 连续 2 次 `changed_input: "none"` → 拒绝执行。

## 外部 skill 比对机制（2026-09-28 新增）

比对外部开源 skill 时，**只搬机制，不搬 bug，也不搬不适合本链路的实现**。

**搬运前四问**：
1. 它的前提和 ours 一样吗？（例：外部串行 i2i 因为服务端并发=1，ours 能并发 → 抄结论不抄约束）
2. 它的实现依赖它的平台吗？（macOS fontconfig / 本地 ffmpeg 老版本 / 固定路径 → 不能直接抄）
3. 它有 bug 吗？（抄机制时逐行读，被自己验证过的坑标注出来）
4. 它和 ours 已有的强项冲突吗？（ours 更强的不许被拉低）

**明确不引入的**（已评估后否决，附理由）：
| 外部做法 | 不引入理由 |
|---|---|
| 四宫格固定方案数 | 平台差异，ours 单方案直出 |
| 每镜时长按台词字数折算 | ours 的 3/5/10/18 档位是与用户协商过的硬约束 |
| ~~模型音轨分层保留~~ | 【2026-09-29 反转】已改为**默认保留**模型音轨作交付配音（render-contracts §8）；`NO_AUDIO=1` 才弃 |

## 纪律
- 修服务先备份（`media.py.bak-原因-日期`）；改 md 用断言替换，失败即停。
- 每次经验要有**证据行**（能指到具体文件/行/实测输出），否则不沉淀。
  推测必须标「推测」并写明待验证条件。
- 大改动走"外科手术"（最小 diff），禁止顺手重构无关部分。
- **改权威文件前先 `grep` 确认没有别处与之矛盾**——本次就是在
  `render-contracts.md` 里发现「§4.9 模板写 `[--ref <SCN>]`」与「§4 禁止资产板当 ref」
  自相矛盾，而**矛盾本身**才是 bug 源头。
- ⚠️ **通配符枚举编号目录是本项目头号陷阱**：`X-0*` 只能匹配到 `-01..-09`，
  一旦段数 ≥10（本项目标准是 12~16 段）就静默漏段。正确写法：
  `find -maxdepth 1 -type d -name 'X-*'` + 纯数字后缀校验 + 稳定排序。
- ⚠️ **凡是「枚举一批文件后合并/统计」的脚本，必须有对账**：
  ①条目数 vs 期望数（manifest / 清单）；②产物量 vs 输入量。
  没有对账的脚本 = 把 bug 静默固化成「看起来正常」。本项目已有三个实例：
  `qa_manifest`（refs / keyframes 对账）、`qa_videos`（缺段 / 孤儿段）、
  `concat_episodes`（段数 + 时长双对账）。
