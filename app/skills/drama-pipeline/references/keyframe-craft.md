# 关键帧工艺细则（帧词怎么写才不出重复人）

> `render-contracts.md` §4 是契约（必须/禁止），本文件是配方（怎么写）。
> 规则分级沿用 §0：`structural_invariant` 可阻断，`craft_default` 只 warn。

## 1. 九段式帧词配方（有序，不可调换）

帧词按显式标签分段，**每段一行**。标签式结构让模型按段处理，信息不混。

```
[画幅]      16:9 横屏
[人数]      画面中仅有 2 人：赤焰、冰璃，每人只出现一次，一人一实体。
[CHARACTER] 赤焰立于纪念碑左侧台阶，冰璃立于右侧，二人相距约三步，正面朝向同一方向。
            身份与本集造型严格沿用参考图1、参考图2，不重描五官、发色、瞳色与服装细节。
[BACKGROUND] 广场上无其他人物，无围观群众，无背景剪影人形。
[SCENE]     天穹城中央广场，白色巨碑立于正北，阶梯自碑前向南下延，地面为浅灰石砖，
            东西两侧为对称廊柱，远处地平线可见云海。
[CAMERA]    中全景，平视，机位在两人南侧约十二米，略低于胸口，朝北。
[LIGHT]     主光自东南高位斜射，色温偏冷；阴影落在人物西北方；无逆光剪影。
[STYLE]     次世代国漫 3D CG 画风，顶尖国产 3D 建模，分层布料与物理衣摆，细腻发丝根根烘焙，
            电影级渲染光影，玄幻质感与高级感，masterpiece, best quality, 8K resolution
[EXCLUDE]   禁止任何角色重复出现、禁止背景路人、禁止同角色多视角并列、禁止分屏拼接、
            禁止镜像倒影分身、禁止文字水印。
            exactly 2 characters in one single unified shot, one instance of each,
            no duplicated characters, no repeated faces, no extra people, no crowd,
            no background figures, no split screen, no collage, no multiple views,
            no mirror or reflection duplicates, no text, no watermark.
```

**为什么分 9 段而不是一段散文**（`reviewed_invariant`）：
- 模型对**结构性文本**的遵循度高于同长度的散文——标签本身就是位置编码；
- 每段职责单一，改一段不会连坐其他段，便于 A/B 单变量实验；
- 机检可按段做残留扫描（动作动词、人物重名、禁忌词）。

## 2. 顺序为什么不能换

| 位置 | 段 | 理由 |
|---|---|---|
| 1 | `[画幅]` | 权重最高，早期 token 影响全局构图 |
| 2 | `[人数]` | **必须紧随画幅**。人数是排除性约束，需在场景/风格引发人物联想**之前**落地 |
| 3 | `[CHARACTER]` | 身份来自 ref，此段只写「谁 + 站在哪 + 姿态」，不写外貌 |
| 4 | `[BACKGROUND]` | 紧跟人物段，明确「其余一切人形都不许有」 |
| 5-7 | `[SCENE]`→`[CAMERA]`→`[LIGHT]` | 世界 → 视点 → 光，顺序符合渲染管线 |
| 8 | `[STYLE]` | 风格档逐字并入，位置靠后避免稀释前面的约束 |
| 9 | `[EXCLUDE]` | 末尾兜底，**中英双语**（中文字面理解 + 英文模式匹配） |

> ⚠️ 末尾 `[EXCLUDE]` 只能约束「模型自己多画的」。
> **模型从 ref 里读进来的重复（资产板人群、多姿态面板）末尾句压不住**——
> 那必须靠 §4.1/§4.3 在 ref 层解决。这就是 `[人数]` 必须前置的原因。

## 3. 纵深三段（16:9 群戏专用）

横屏 1.78 的画幅，**横向铺开必然糊成一片并排站立**。改用纵深分层：

| 层 | 位置 | 承担 |
|---|---|---|
| 前景 | 画面下缘 1/6，**虚化**（1~2 个局部形：肩/手/兵器/衣摆） | 代入感、遮挡关系 |
| 中景 | 画面中部，**清晰** | 叙事主体，通常 1~2 人 |
| 后景 | 画面上缘，**低对比+低饱和**（建筑/云海/旗帜） | 空间纵深 |

- 三层之间必须有**遮挡关系**（前景遮住中景一部分），否则三层读起来是三张贴图。
- 后景**禁止出现人形**；若必须有，写成建筑构件或纯色块。

## 4. 焦点层级（`craft_default`）

同框多人时，用三档把注意力排成单向链，**不允许平权**：

1. **锐利 + 高对比 + 居中偏前** = 本镜视点人物（唯一）
2. **正常清晰 + 次对比 + 三分位** = 交互对象
3. **柔焦/降饱和/压暗 20~30%** = 背景层，只提供体量不抢视线

- 平权（三人同样清晰同样亮）会诱导模型把三人画成重复的同类构图 → **重复人**。
- 2 人镜：一人对镜头一人过肩背对（过肩镜自带层级，优于并排）。

## 5. 「与上一镜相同」句（连戏锚）

同一场景的连续镜头，帧词加一行：

```
[CONTINUITY] 与上一镜同场景、同站位、同光线、同道具，仅景别由中全景推为近景。
```

- 只在**段缝**需要（kf2 承接上一段 kf2 时）。
- 差异只允许**景别或姿态一个维度**；同时改两个维度模型就开始自由发挥。
- ⚠️ 不写「与上一镜相同」的图，模型会重新采样场景 → 段缝跳切。

## 6. `[EXCLUDE]` 写什么（按帧定制，不许套用模板）

**通用三条**（每帧都写）：
- 禁止任何角色重复出现 / no duplicated characters, no repeated faces
- 禁止额外人物与围观群众 / no extra people, no crowd, no background figures
- 禁止分屏、多视角并列、拼贴、镜像分身 / no split screen, no multiple views, no collage, no mirror duplicates

**按本帧风险追加**（本帧最可能出什么就禁什么）：

| 本帧风险 | 追加排除项 |
|---|---|
| 持武器/发光道具 | `禁止武器复制多份、禁止多余光刃` / `no duplicated weapon, no extra blades` |
| 变身/换色特效 | `禁止同角色不同色版本并列` / `no multiple color variants of the same character` |
| 大群战 | `禁止可辨识面孔的额外人形` / `no recognizable faces among background figures` |
| 镜面/水面/屏幕 | `禁止倒影中出现完整人形` / `no full human figure in reflection` |
| 载具/飞行器 | `禁止载具复制` / `no duplicated vehicle` |

> **排除项必须针对本帧**，不是把整张禁用清单贴上去。无关排除词会稀释真正重要的那一条。

## 7. 竖向空间提示（仅 9:16）

`[CAMERA]` 段加纵向分层：上方 1/3 天幕/建筑顶 / 中部主体 / 下缘前景。
**16:9 不要写这一套**（写了会诱导模型做上下分栏）。

## 8. 形容词纪律

- **只修饰「物理事实」**（材质、颜色、光质），**不修饰「渲染质量」**
  （高质量、顶级、精美、震撼、令人震撼 = 零信息量）。
- **禁止用增加形容词回应重复缺陷**——见 `render-contracts.md` §4.8。
- 形容词密度自检：一句里 >2 个纯评价形容词 → 删到 1 个或 0 个。
- **「静」是合法输出，不许为防呆板而加词**（2026-09-28 补）：
  帧词是静态定格，「某人一动不动地站着」完全合法，而且常常是正确的。
  静可以是：主动倾听 / 专注判断 / 拒绝 / 威胁 / 震惊 / 隐瞒 / 蓄势 / 权力表态。
  - ❌ 错误做法：怕画面呆板，于是在帧词里加「微风拂动发丝」「眼中闪过一丝犹豫」——
    帧词层禁动作动词，这些词要么被机检拦下，要么让模型在静帧里画出诡异的小动作。
  - ✅ 正确做法：把「静得有张力」交给**姿态**（重心/肩线/手部位置/视线落点）
    与**光影**（硬光压半脸 / 逆光勾轮廓）来表达。

## 9. 帧词自检清单（出图前逐条打勾）

**结构层**
- [ ] `[画幅]` 是首段，`[人数]` 是第二段
- [ ] 人数数字与实际出场角色数一致，且未点名单镜不需要的角色
- [ ] 无外貌重描（无「黑发金瞳/red hair」类词）；如写了标志色，只写了**一个颜色词**
- [ ] 无动作动词残留
- [ ] 无两时刻拼接（同一段内状态自洽）
- [ ] `[EXCLUDE]` 含通用三条 + 至少一条本帧专属
- [ ] 连戏段有 `[CONTINUITY]`
- [ ] 3+ 人镜：非并排站立，有纵深分层与遮挡

**条件层**
- [ ] ref 数 ≤2，且无资产图（父目录不是 `assets/`）
- [ ] 画面可读文字 = 0
- [ ] 接触/交接类动作同时 ≤1
- [ ] 精确口型 = 0

**预算层**（详见 `video-prompt-craft.md` §7 事前复杂度预算）
- [ ] 字数 ≤1200（>1500 需降并发或删句）
- [ ] 7 轴复杂度预算已过一遍，超阈项已按 6 选 1 处置并落台账
- [ ] 世界规则无禁用元素（`world-rules.md` §2）

## 10. 失败处置（`reviewed_invariant`）

出图出现重复人/多余人物时，**按此顺序换层级**，禁止在同一条提示词上叠加形容词：

| 序 | 动作 | 为什么 |
|---|---|---|
| 1 | **查 refs**：有没有资产板 / 有没有 >2 张 | 最高概率根因（已在《花语战歌》12/12 段命中） |
| 2 | **减 ref**：3 张→1 张，把另外两个写进 `[BACKGROUND]` 并要求剪影 | 3+ ref 一致性 <50% |
| 3 | **拆镜**：把 N 人同框拆成单人镜 + 过肩镜 | 结构问题不靠词能解 |
| 4 | **前置人数 + 加 `[EXCLUDE]`** | 只在根因是「模型自己多画」时有效 |
| 5 | **改换景别/机位** | 换构图上下文，脱离原图条件 |

> 处置完仍失败 → 判定为该构图在本模型上不可达，**记录并换构图方案**，
> 不要进入「再试一次原样重投」的循环（失败也扣费）。

## 11. BGM cue 功能词表（`craft_default`，2026-09-28 补自 zhaihao118 storyboard_config.json bgm.mood）

zhaihao118 在 `storyboard_config.json` 的 `bgm.mood` 字段里为每半段定义了 7 种
BGM 功能词，比我们的纯文字描述更结构化。建议把以下词表纳入视频词【音效】段的
BGM 标注规范：

| 功能词 | 含义 | 时机 |
|--------|------|------|
| `establishing` | 建立世界基调 | 每集第 1 段 |
| `tension_build` |  tension 持续累积 | 冲突铺垫段 |
| `release` | 张力释放 | 转折/反转后 |
| `emotional_peak` | 情绪顶点 | 高潮对话/动作 |
| `reflective` | 反思/余韵 | 静场/沉默段 |
| `transition` | 转场过渡 | 段间衔接 |
| `resolve` | 收束 | 每集末段 |

使用格式：在【音效】段写 `<BGM: emotional_peak>`，模型据此调整配乐情绪方向。
> ⚠️ 本词表目前只是建议，尚未写入 qa_manifest.sh 检查规则。
> 落地前需先实测：写 BGM cue 是否会显著改善视频情绪对齐度。
